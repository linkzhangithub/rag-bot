# RAG 幻觉问题解决方案

## 什么是 RAG 幻觉

RAG（Retrieval-Augmented Generation）幻觉指的是语言模型在基于检索到的文档进行回答时，生成的内容与文档事实不符或完全虚构的现象。

## 解决 RAG 幻觉的主要策略

### 1. 检索优化

**提高检索准确性：**
- 使用更高质量的嵌入模型（如 Embedding-2）
- 调整相似度阈值，过滤低相关性文档
- 增加 Top-K 值，获取更多候选文档
- 使用混合检索（关键词 + 语义）

**查询改写：**
- 将用户问题改写为更适合检索的形式
- 使用同义词扩展、Query Expansion 技术

### 2. 文档处理优化

**文本分割策略：**
- 合理设置 chunk 大小（500-1000 tokens）
- 设置适当的 overlap（100-200 tokens）
- 保持语义完整性，避免切分句子

**文档质量控制：**
- 去除低质量、重复或冲突的文档
- 对文档进行预处理和清洗

### 3. 提示词工程

**明确指令约束：**
- 强制要求模型仅使用提供的参考文档
- 明确说明当没有相关信息时应如何响应
- 禁止模型使用外部知识

**结构化提示词：**
```
你是一个严格基于参考文档的问答助手。

核心指令：
1. 仅使用提供的参考文档内容回答问题
2. 如果文档中没有相关信息，请直接回答"无法回答"
3. 不要编造答案，不要使用文档外的知识

参考文档：
{context}

用户问题：
{question}
```

### 4. 参数调整

**降低生成随机性：**
- 设置较低的 temperature（0.1-0.3）
- 调整 top_p 参数（0.5-0.7）
- 使用更高精度的模型

**启用事实核查：**
- 在生成后验证答案与源文档的一致性
- 使用 Reranker 重新排序检索结果

### 5. 事后验证

**答案验证机制：**
- 将生成的答案与源文档进行比对
- 检测是否存在虚构内容
- 对可疑答案进行标记或拒绝

**引用追踪：**
- 要求模型提供答案的来源引用
- 显示相似度分数，让用户了解答案可信度

### 6. 架构优化

**使用 RAG Fusion：**
- 将多个检索结果融合为统一上下文
- 使用 reciprocal rank fusion 合并排序

**分层检索：**
- 先进行粗检索，再进行精检索
- 使用多阶段验证机制

## 实践建议

| 方法 | 复杂度 | 效果 | 推荐优先级 |
|------|--------|------|-----------|
| 优化提示词 | 低 | 中 | ★★★★★ |
| 调整温度参数 | 低 | 中 | ★★★★☆ |
| 提高检索精度 | 中 | 高 | ★★★★★ |
| 答案验证 | 高 | 高 | ★★★☆☆ |
| RAG Fusion | 高 | 高 | ★★★☆☆ |

## 总结

解决 RAG 幻觉需要从多个维度综合优化：
1. 确保检索到高质量的相关文档
2. 通过提示词严格约束模型行为
3. 调整生成参数降低随机性
4. 建立答案验证机制

没有单一的银弹解决方案，需要根据具体场景组合使用多种策略。
